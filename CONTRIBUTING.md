# Contributing to PickleCoach-AI

Thank you for your interest in contributing to PickleCoach-AI! To maintain a high standard of code quality and project organization, please follow these guidelines.

## 🚀 Getting Started

1.  **Fork the repository** and create your branch from `main`.
2.  **Install dependencies** for the specific module you are working on (frontend, backend, or ai).
3.  **Run the project locally** using Docker Compose to ensure consistency.

## 🌿 Branch Naming Convention

-   `feature/` : For new features (e.g., `feature/ai-pose-feedback`)
-   `fix/` : For bug fixes (e.g., `fix/webrtc-handshake`)
-   `docs/` : For documentation updates (e.g., `docs/api-endpoints`)
-   `refactor/` : For code refactoring

## 💬 Commit Message Convention

We follow the [Conventional Commits](https://www.conventionalcommits.org/) specification:

-   `feat`: A new feature
-   `fix`: A bug fix
-   `docs`: Documentation only changes
-   `style`: Changes that do not affect the meaning of the code
-   `refactor`: A code change that neither fixes a bug nor adds a feature
-   `perf`: A code change that improves performance
-   `test`: Adding missing tests or correcting existing tests

Example: `feat(ai): add real-time pose estimation feedback`

## 🛠️ Development Workflow

-   **Pull Requests**: Ensure your PR has a clear description of the changes and links any relevant issues.
-   **Code Review**: All PRs require at least one approval before merging.
-   **Testing**: Please include unit tests or evidence of manual verification (e.g., screenshots/logs) with your PR.

## ⚖️ Code of Conduct

Help us keep this project open and inclusive. Please be respectful and professional in all interactions.
